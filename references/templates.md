# 可裁剪的交付模板

这些是帮助执行和审阅的字段，不要求为低影响改动生成额外文件。优先复用项目已有的任务和验收入口。

## 审计发现

```text
编号 / 优先级 / 证据状态：
受审仓库、完整 SHA、工作树及未提交增量：
问题与触发前提：
证据：当前文件行号、调用链；复现命令与实际结果
根因：规则/状态/数据归属在哪个边界断开
影响：能确认的范围；尚未证实的线上或专业影响
最小方案与必要性：
成本、兼容影响、可能副作用：
验证：修复前失败，修复后预期；需保留的正常路径
信息缺口：
```

发现清单不能只列文件长度、TODO 数量或工具扫描告警。每个需要整改的条目至少能解释一个真实故障或后续修改场景；没有足够问题时可以明确写“未发现”。

## 渐进整改任务

```text
任务：对应哪项发现；业务完成标准
基线：目录、分支、SHA、已有增量处理、回退节点
范围：涉及文件/模块、职责方、接口/数据变更
步骤：先补什么测试，再做哪一个最小变化
验证：正常/失效/重复/恢复；专项与必要的跨边界检查
风险与回退：代码和数据分别如何兼容；不回退到旧业务快照
交付：文件差异、实际结果、已知失败、未验证项、Git/发布状态
停止条件：用户要求的审阅点；本轮不自动接续其他任务
```

若存在多个独立仓库，将任务分别交给对应维护方；审计另一方代码不表示取得修改其账号、余额或商业规则的授权。

## 修复后的简短回执

```text
本次完成：问题与最终行为
安全节点：分支 / 基线 SHA；原有增量状态
实际修改：文件链接与关键逻辑差异
验证：命令；通过/失败/错误/跳过分别计数；模拟与真实分别说明
已知失败：首轮症状、基线对照与复测，是否仍未定位
残余风险：并发边界、兼容、未验收的外部或专业结果
状态：是否暂存/提交/推送/合并/部署；按授权停下
```

例如 455 项中 453 通过、1 错误、1 跳过；错误项单独复测通过，应保留两次结果，不能改写为“455 项全过”。这只是表述示例，不是测试数量门槛。

## 可直接发起的任务提示词

审计：

> 使用 $engineering-audit-remediation 对当前项目和指定远端做只读工程审计。先核实版本与结构，再按风险深入，提供实际代码证据、范围限制及可分批任务；本轮不改代码。

已授权单项修复：

> 使用 $engineering-audit-remediation 复核发现 F1，只实施这一项。保护已有增量并建立不含新提交的回退节点，先复现再最小修复，完成相关验证与差异说明。不要提交、推送、部署或继续下一项。

先计划待确认：

> 使用 $engineering-audit-remediation 为指定发现给出具体步骤和修改范围，只读核查后等待确认，再实施。
